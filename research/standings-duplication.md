# Standings Duplication Analysis

Four pairs of duplicated derivations in the reports subsystem.

## Comparison Table

## Notes

- **Pair 1** could be consolidated by extracting the pilot list construction into a shared function that takes an abstract data source (interface with `profiles`, `teams`, `participations`, etc.). The export version could pass a thin adapter.
- **Pair 2** is the most valuable consolidation opportunity — the row-building logic is structurally identical, but the differences (throw vs. tolerate an empty match, `isTied`/`reviewOpen`/`detail`) must become parameters. A shared `buildStandingsRows` function would eliminate ~60 lines of duplicate code.
- **Pair 3** is a simple helper extraction — move `FlightDetail` construction into a shared utility.
- **Pair 4** could use a base class `BaseReportOptions` with shared parsing logic, with concrete classes extending it for report-specific options.
