# Ticket 007 — F3J Fixed Late-Landing Penalty

- **Category:** Scoring Engine
- **Priority:** Medium
- **Status:** ready

## Context

The F3J business doc (`f3j.md`) states, under *Computational Rules* ("not configurable or presented to the contest director"), that "A late landing does not receive any landing bonus" and "A late landing incurs a 30 point penalty. This penalty stays with the round." The architecture doc (`discipline-scoring.md`) requires F3J tests to cover "the fixed late-landing penalty". The ticket's original "no fixed penalty amount is given" gap is **resolved**: `f3j.md` line 37 gives the amount (30 points) and the scope (computational rule, not configurable).

## Questions

1. What is the fixed late-landing penalty value for F3J? — **Resolved: 30 points (see Decisions).**
2. Is it configurable per contest, or a fixed constant in the rules? — **Resolved: fixed constant in the profile; not configurable (see Decisions).**
3. How does it combine with the removal of the landing bonus — is it a subtraction from the base points, or a separate penalty component? — **Resolved: subtraction inside the discipline raw score, before group scoring (see Decisions).**
4. Does the late-landing penalty interact with the working-time cap (i.e., is the penalty applied even if the time is capped at the working time)? — **Resolved: yes, the penalty applies to every late landing; the time cap is applied first (see Decisions).**
5. Does the pilot's raw score floor at 0 after the 30-point penalty, the same as the F5J height penalty? — **Resolved: floor at 0 (see Decisions).**
6. Is the 30-point penalty stored as part of the raw component set (computed by the engine) or derived on-the-fly at calculation time? — **Resolved: derived-only, single `lateLanding` status flag (see Decisions).**
7. Which reason/status flags must a late-landing score carry for reporting (e.g., `LateLanding`, a distinct `LateLandingPenalty` flag)? — **Resolved: single `lateLanding` boolean status flag (see Decisions).**
8. How is the 30-point penalty displayed in score-entry and public result views (line item, hidden, or only via the raw score)? — **Resolved: see Decisions (Q8) — individual results view, flight group scores view, score detail view, and score-entry form.**

## Decisions

- **Pipeline placement (Q3, decided):** The 30-point penalty is part of the **discipline raw score**, applied **before** group scoring, in the F5J ticket-005 pattern: for a late-landing F3J score, `raw = max(0, pps × timeFlown + eligibleLandingBonus − 30)`. For a non-late score, `raw = pps × timeFlown + eligibleLandingBonus` (landing bonus per the selected landing table; `eligibleLandingBonus` is 0 for a late landing because the bonus is forfeit). This makes it a *discipline-specific penalty* — explicitly distinct from the contest-level integer `Cumulative Penalty` raw component, zero-score reasons, and administration penalties (per `discipline-scoring.md` stored-data rule 2).
- **Value and configuration model (Q1, Q2):** The 30-point value is a **fixed constant in the F3J profile**, per `f3j.md`'s "not configurable or presented to the contest director" clause. It is **not** a contest-config field and cannot be overridden per contest. Changing it requires a new discipline rules version (per `discipline-scoring.md` profile-contract rule 4).
- **Working-time cap interaction (Q4):** The submitted time must not exceed the working time (`discipline-scoring.md` F3J rule 2). The service caps any time at the working time using the configured fractional-second precision (0–3 decimals), **before** computing `pps × timeFlown`. The 30-point penalty is then applied on top of that. A late-landing score therefore always carries full working-time points **minus 30**, regardless of whether the cap was exercised.
- **Dropped-round interaction:** Because the penalty is inside the raw score, it is **dropped together with the round** when the round is selected as the dropped round — consistent with "This penalty stays with the round" (the penalty attaches to the round's score, not to the pilot across the contest). No "Penalty Not Discarded" rule applies to it (that rule is for `Cumulative Penalty` values, per `discipline-scoring.md` pipeline rule 6).
- **Zero-score interaction:** An out-of-bounds landing produces zero and the 30-point penalty is **not** additionally applied (the round is already zero for the OOB reason; the OOB reason flag supersedes). A late landing and an out-of-bounds landing are mutually exclusive status selections (per `f3j.md` "The screen should not allow the user to enter a time greater than a working time" and the UI zero-field behavior).
- **Negative floor (Q5):** The raw score is floored at 0 **after** the 30-point penalty is subtracted, exactly mirroring the F5J ticket-005 decision. `raw = max(0, pps × timeFlown + eligibleLandingBonus − 30)`. A late landing with 0 seconds of recorded time produces a raw score of 0, not −30. The penalty is computed in full; only the final raw result is clamped. This satisfies the `discipline-scoring.md` verification rule 106 invariant ("scores never become negative where the profile forbids it") and is consistent with the F5J "The lowest score a pilot can receive for their raw score is 0" rule.
- **Storage model (Q6):** The 30-point penalty is **derived-only**. The score record stores a single `lateLanding` boolean status flag (alongside the existing `timeFlown`, `landingTableKey`/`landingPoints`, `outOfBounds`, and `cumulativePenalty` raw components). The 30-point value is a profile constant the F3J raw-score function applies when `lateLanding` is true — exactly the F5J ticket-005 pattern, where the height penalty is derived from the stored altitude and not itself stored. This keeps the "submitted raw components" set equal to what the pilot/official actually entered (per `discipline-scoring.md` stored-data rules 1 and 3), requires no schema migration, and makes recalculation after a landing-table change or a rules-version change deterministic. No new stored field, no new derived field.
- **Reason/status flags (Q7):** The F3J profile declares exactly **one** status flag for late landing: `lateLanding` (boolean). It is **not** a zero-score reason (a late landing does not produce zero; it produces a reduced-but-positive raw score), so it is distinct from the `outOfBounds` / `overFlight` / `motorRestart` / `missingAltitude` / `retirement` zero-reason flags listed in `discipline-scoring.md` rule 48. It is mutually exclusive with `outOfBounds` (the two cannot both be true on a single score). No separate `lateLandingPenalty` flag is introduced — the penalty is a profile constant, not a data value.
- **Display / reporting (Q8):** The 30-point penalty and the `lateLanding` flag are surfaced in **four** places, per the public-site views in `view-contest.md`:

  1. **Overall Individual Results view** (`view-contest.md` §"Overall Individual Results"): The table keeps its existing `Cumulative Penalty` column (the pilot-entered integer, not affected by discipline penalties). The per-round score columns show a **`LateLanding` indicator** (e.g. a small `L` superscript or icon) on any round where the pilot had a late landing. The 30-point penalty value is **not** shown as a number in this view — it is already reflected in the round's raw score. The F5J height penalty is likewise not shown in this view (it is reflected in the round's raw score and shown as a line item in the score detail).
  2. **Flight Group Scores view** (`view-contest.md` §"Flight Group Scores"): The **`Penalty`** column shows the total **rules-violation-type** discipline-specific penalty for that flight (for F3J: 30 if late landing, 0 otherwise; for F5J: 0 — the height penalty is *not* a rules-violation penalty and does not appear in this column). A **`LateLanding` chip** is also shown on the row when `lateLanding` is true, alongside the existing `OutOfBounds` / `MotorRestart` / `OverFlight` chips. The chip indicates the *reason* for the penalty; the `Penalty` column shows the *value*. For **F5J** specifically, the view additionally contains two height-specific columns: a **`Height`** column showing the recorded launch altitude in meters, and a **`Height Penalty`** column showing the calculated height penalty in points (derived from the recorded height and the contest's reference height, minor, and major penalty configuration). These two columns are distinct from the generic `Penalty` column because the height penalty is an *intrinsic part of the F5J task*, not a rules violation.
  3. **Score detail view** (expanded per-pilot score breakdown): Shows an explicit line `Late landing penalty: -30` between the landing-bonus line and the raw-score total. The value is client-derived from the `lateLanding` flag and the profile constant (30); it is **not** a new field in the public projection. For F5J, the analogous line is `Height penalty: -X` where X is the computed height penalty.
  4. **Score-entry form**: The 30 is not a user-editable field — it is a fixed rule. When the user toggles `Late landing`, the form zeroes and disables the landing-bonus selection (per `f3j.md` "Indicating a late landing should zero the landing bonus option and make it unavailable for selection") and the previewed raw score drops by 30 + the forfeited bonus.

  **Cross-discipline note:** The `Penalty` column in the Flight Group Scores view is a **generic, discipline-agnostic** column for **rules-violation-type** discipline-specific penalties only. For F3J it shows the late-landing penalty (30 or 0). For F5J it shows 0 (the height penalty is intrinsic to the task and is shown in its own `Height Penalty` column, not here). For disciplines with no per-flight penalty (e.g. ALES, Thermal Duration), the column shows `-` or `0`. The column does **not** include the contest-level `Cumulative Penalty` (which remains a separate column in the individual and team results views) and does **not** include intrinsic task components like the F5J height penalty (which has its own dedicated column).

  **F5J height columns:** The F5J Flight Group Scores view adds two columns that are not present for other disciplines: **`Height`** (recorded launch altitude in meters, from the stored raw component) and **`Height Penalty`** (calculated penalty in points, derived from the recorded height, the contest's reference height, minor penalty per meter, and major penalty per meter). These are profile-specific columns — the F5J profile's score-entry schema declares them, and the view renders them only for F5J contests. For F3J, ALES, and Thermal Duration these columns are absent.

- **F5J height penalty display (clarification):** The F5J height penalty is **not** shown in the Overall Individual Results view (it is reflected in the round's raw score). It **is** shown in the Flight Group Scores view in its own **`Height Penalty`** column (alongside a **`Height`** column showing the recorded altitude in meters) and in the score detail view as a `Height penalty: -X` line item. It does **not** appear in the generic `Penalty` column because the height penalty is an intrinsic part of the F5J task, not a rules violation. This is consistent with the F3J late-landing penalty treatment (which *does* appear in the generic `Penalty` column because it is a rules-violation-type penalty).

## Acceptance criteria

- The F3J profile computes the raw score for a late-landing score as `max(0, pps × timeFlown + eligibleLandingBonus − 30)` where `eligibleLandingBonus` is 0 for a late landing.
- The F3J profile computes the raw score for a non-late score as `pps × timeFlown + eligibleLandingBonus`.
- The 30-point value is a profile constant, not a contest-config field, not override-able, and not presented in the contest configuration UI.
- The submitted time is capped at the working time (using the configured fractional-second precision) **before** computing `pps × timeFlown`; the penalty is applied after the cap.
- When a late-landing round is dropped, the 30-point penalty is dropped with it and does not affect the pilot's contest total.
- The 30-point penalty is **not** folded into the `Cumulative Penalty` raw component; that component remains an independent, required integer input.
- A score with both a late-landing flag and an out-of-bounds landing flag is invalid and rejected (mutually exclusive statuses).
- The score record stores a single `lateLanding` boolean status flag; no new stored field and no new derived field are introduced for the penalty.
- The `lateLanding` flag is not a zero-score reason; it is distinct from the `outOfBounds` / `overFlight` / `motorRestart` / `missingAltitude` / `retirement` reason flags.
- **Overall Individual Results view:** The `Cumulative Penalty` column is unchanged. Per-round score columns show a `LateLanding` indicator on late-landing rounds. The 30-point penalty value is not shown as a number in this view.
- **Flight Group Scores view:** The `Penalty` column shows the total rules-violation-type discipline-specific penalty for the flight (30 for F3J late landing, 0 for F5J, `-`/`0` for disciplines with no per-flight penalty). A `LateLanding` chip is shown when `lateLanding` is true. For F5J, two additional profile-specific columns are shown: `Height` (recorded launch altitude in meters) and `Height Penalty` (calculated height penalty in points). These columns are absent for non-F5J disciplines.
- **Score detail view:** Shows an explicit `Late landing penalty: -30` line between the landing-bonus line and the raw-score total; the value is client-derived from the `lateLanding` flag and the profile constant.
- **Score-entry form:** When `Late landing` is toggled, the form zeroes and disables the landing-bonus selection and the previewed raw score drops by 30 + the forfeited bonus.
- Golden fixtures include: (a) a late landing with a capping time, (b) a late landing with a non-capping time, (c) a late landing where the raw score floors at 0, (d) a late-landing round that is dropped, and (e) a late-landing score in each of the three group-score modes (`Raw`, `Normalized`, `Time`).
- The service and offline calculation library pass the same golden fixtures.
