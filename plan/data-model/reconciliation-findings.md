# Data Model Reconciliation Status

Where `plan/data-model` stands against `plan/architecture-requirements`, `plan/business-requirements`, the pre-implementation tickets, and the owner's design handoff of 2026-10-02. The earlier long list of findings is in the git history of this file; this document records what was resolved and what is still open.

Rule used: architecture requirements win over the data model, and business requirements win over both. Where a decision made during this work differs from a requirement, the requirement was updated, and those updates are listed below.

## Summary

- 47 entities in the ERD, all documented, and a new [contest-options.md](contest-options.md) that defines every setting a director can make.
- The ERD, the entity documents, and the README agree field by field. Both Mermaid diagrams render.
- Everything that blocked writing models and repositories is resolved. The remaining items are in the next section. None of them changes the shape of a core table, except the lock model.

## Open on the data model

| ID  | Item                                               | What is open                                                                                                                                                                                                                                                                                                                   |
| --- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| O-1 | Group and score locks                              | The architecture and business documents require locks at score, group, round, and contest level. The model has contest and round locks only, and no group entity. Recommendation: a `RoundGroup` entity (`round_id`, `group_number`, `status`) and a lock with actor and time on `ScorePlaceholder`, evaluated hierarchically. |
| O-2 | Moving a scored assignment                         | The model says a scored assignment cannot be moved. `move-pilot.md` (business) allows it with a choice to reset or transfer the score. Either update the business and architecture documents to match the model, or reverse the decision and add `existing_score_handling` to the `Moved` row.                                 |
| O-3 | Account concepts are missing from the requirements | Guest, local, and deleted-user accounts, the public profile, claiming, and the deletion flow are in the entity documents but not in the architecture `accounts.md` or the business `accounts.md`. Also decide which account kind a verified-email anonymous publisher is.                                                      |
| O-4 | `Team.pilot_totals`                                | The team pilot count is now the core option `team_pilot_count`, and the team total is derived, so `Team.pilot_totals` should be removed from `team.md`, the ERD, and the README.                                                                                                                                               |
| O-5 | Discipline field definitions                       | `DisciplineScoreField` allows `options` only for `enum`, but `enum` is not in its type list. `zero_reason_code` points to an entity that no longer exists (it is now `DisciplineRule.rule_key`). The architecture also wants unit, precision, and field kind (input, status flag, derived) on every field definition.          |
| O-6 | `DisciplineProfile` types                          | `created_by` and `superseded_by` are strings. They should be an Account foreign key and a profile id. The purpose line still says children are keyed by `discipline_profile_id` and `version`, but the version is on the profile row.                                                                                          |
| O-7 | Contest times                                      | The documents say start and end are "in the contest's timezone", against the rule that everything is stored in UTC. Store UTC plus the `timezone` field.                                                                                                                                                                       |
| O-8 | Physical design wording                            | The README says PostgreSQL enums and ISO 8601 strings. The architecture says a platform-agnostic relational schema, and the client uses IndexedDB or SQLite. Reword to say enums are text with check constraints off the server.                                                                                               |
| O-9 | Optional: invitation delivery as its own table     | Delivery outcomes are a JSON array on `Invitation`. The architecture says issuance and delivery are separate and auditable. A child table is possible later.                                                                                                                                                                   |

## Resolved

| Area                   | What changed                                                                                                                                                                                                                                                                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Documents and diagrams | The README catalog, the ERD, and the entity documents are consistent. The ERD uses aligned Mermaid keys, a rewritten relationship section, and a grouped README graph. A new Sync Scope section classifies every entity. `RoundConfig` is replaced by `Round`.                                                                           |
| Invitations            | An invitation is a reusable link with the states `Active`, `Replaced`, `Revoked`, and `Expired`, an idempotency key, and the account that redeemed it.                                                                                                                                                                                   |
| Publication            | Publication is separate from the contest. `PublicationIdentity` has a nullable contest and a public-profile owner. `PublicationProjection` holds successful publishes only. `PublicationParticipant` supports redaction, and `DelistRequest` handles delisting. Contest deletion no longer has a status and never removes a publication. |
| Visibility             | Visibility is `Unlisted` or `Public`, with an administrator-only `Delisted`. Hiding overall results is a contest control that withholds standings as of a round.                                                                                                                                                                         |
| Landing tables         | Immutable, not tied to a discipline. A profile names a system default, the contest selects any table, and scores store the selected entry.                                                                                                                                                                                               |
| Contest options        | Defined in [contest-options.md](contest-options.md). A configuration revision stores the full resolved settings, the current one is the highest revision number, profiles carry default options, and presets are documented.                                                                                                             |
| Calculation output     | `FlightResult`, `ParticipationStanding`, and `TeamStanding` are stored but always recomputable from the raw components, stamped with the revisions they were computed under, and written only by the calculator.                                                                                                                         |
| Cumulative penalty     | One nullable value per flight, applied only by the director, never dropped. Participants do not enter it. `ContestPenalty` is removed.                                                                                                                                                                                                   |
| Participants           | A profile is always owned by one director and never shared. `ParticipantAccountLink` has a status and an origin, `ParticipantDirectoryEntry` holds what a person offers to directors, and a participant controls how they appear in results through their public profile. Participant email is optional.                                 |
| Participation          | `retired_at_round` replaces the status. A role is on the participation with a name snapshot. Numbers come from one sequence, `scoring_uuid` is a random v4, and the identity is read from the profile.                                                                                                                                   |
| Matrix                 | `LateAdd` assignments with a fixed group capacity. Lane is optional, set by a `lane_mode` option. Re-flights are redesigned, with `ReFlightParticipant`.                                                                                                                                                                                 |
| Sync and audit         | `Installation` and `InstallationActivation`, a per-scope mutation sequence with a separate director stream, silent conflict records, tombstones kept 90 days after acknowledgement, and a shared authority list.                                                                                                                         |
