# Installation

**Relationship to architecture-requirements:** plan/architecture-requirements/data/synchronization-and-audit.md, plan/architecture-requirements/offline-synchronization.md  
**Purpose:** A contest director's app instance: the web app or the desktop app on one device. It identifies where a change came from, what it has synchronized, and which system data it holds. The director sees installations by label, for example in "Contest is currently active on [Device A]". Participant devices are not installations; they reach a contest through an invitation.  
**Identifier:** `id` (UUIDv7)  
**Parent entity:** Account (the owning director)  
**Child entities:** None

## Relationships

- Belongs to the director's Account (`owner_account_id`)
- Referenced by InstallationActivation, SyncCursor, MutationRecord (`source_installation_id`), and AuditEvent (`installation_id`)

## Fields/Properties

| Field              | Type        | Required | Default | Description                                                                                                        |
| ------------------ | ----------- | -------- | ------- | ------------------------------------------------------------------------------------------------------------------ |
| `id`               | UUIDv7      | Yes      | -       | Primary key. Generated by the installation                                                                         |
| `owner_account_id` | UUIDv7      | Yes      | -       | FK Account of the director who owns the installation                                                               |
| `label`            | String      | Yes      | -       | A name the director recognizes, for example "Field laptop"                                                         |
| `platform`         | enum        | Yes      | -       | `Web`, `Windows`, or `Other`                                                                                       |
| `created_at`       | timestamptz | Yes      | now     | When the installation was registered                                                                               |
| `last_seen_at`     | timestamptz | No       | -       | Last time the server heard from it                                                                                 |
| `last_sync_at`     | timestamptz | No       | -       | Last time it completed a synchronization                                                                           |
| `system_data_seq`  | bigint      | Yes      | 0       | The last system-data sequence it has applied. System data (profiles, system roles, landing tables) only comes down |
| `revoked_at`       | timestamptz | No       | -       | When the director revoked the installation, for example a lost device. A revoked installation cannot synchronize   |

## Invariants and Constraints

- An installation is registered while connected, by an authenticated session of its owning account
- `system_data_seq` only increases
- A revoked installation is rejected on every later synchronization and can no longer hold authority over a contest
- Revoking an installation does not delete changes it already submitted
- Participants do not register installations. Their submissions carry an opaque device identifier

## Lifecycle

Registered, used, and optionally revoked. Never deleted, because mutations and audit events refer to it.

## Privacy and Scope

- Backend only. Visible to its owner and to system administrators
- Not synchronized as a record, although an installation knows its own identifier

## Audit and Synchronization

- Registration and revocation are recorded in application logs and as AuditEvents when they affect a contest
- Not synced
